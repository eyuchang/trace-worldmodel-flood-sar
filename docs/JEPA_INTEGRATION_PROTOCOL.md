# V-JEPA Integration Protocol

## System boundary

The integration connects the Flood-SAR prototype to the open-source V-JEPA 2.1
visual encoder without changing TRACE commitment semantics. V-JEPA supplies a
frozen visual representation. A separately trained, action-conditioned Flood-SAR
head maps controller-visible structured inputs and visual features to calibrated
route outcomes. TRACE records the resulting provenance and applies the existing
technical and authority gates.

The V-JEPA self-supervised pretraining predictor is not used as the Flood-SAR
action predictor. The transparent surrogate remains the default and is unchanged
when no learned adapter is explicitly configured.

## Observation and feature provenance

`RouteWorldModelRequest` contains only controller beliefs, declared forcing and
sensor parameters, static route susceptibility, controller-known asset telemetry,
and a content-addressed visual observation identifier. Dynamic simulator truth is
not part of the request schema.

The synchronized simulator camera, `flood-sim-drone-rgb-v2`, captures a clip at
the drone observation time. Its latent sensor snapshot is stored only in an audit
manifest. The controller receives the visual observation identifier, integrity
hash, sensor version, and timestamp. Nonvisual reports preserve this provenance
without refreshing the visual timestamp.

Offline encoding verifies the observation identifier, frame digest, audit-manifest
digest, and observation digest. It rejects unsafe identifiers, symlinks, malformed
archives, and non-finite features. Cache files are written atomically and loaded
with NumPy pickle support disabled. Missing declared features fail closed rather
than invoking an undeclared surrogate fallback.

## Predictor, calibration, and support

The development predictor is ridge-regularized linear regression over action
one-hot vectors and one of four declared input modes: structured, visual, fused,
or fused with episode-shuffled visual features. A constant model is included as an
additional control. Normalization is fitted on training episodes, the ridge penalty
is selected on the tuning split, and isotonic success calibration is fitted on a
separate calibration split.

The checkpoint records normalization parameters, support bounds, residual scales,
the action schema, encoder provenance, calibration arrays, and the training-dataset
hash. Runtime support combines feature-range checks with standardized distance from
the training distribution. Residual calibration error contributes to reported
uncertainty.

## TRACE runtime integration

`DynamicMissionController` accepts an optional route-world-model adapter. Learned
predictions traverse the same candidate, evidence, TRACE assessment, consumer, and
commitment path as surrogate predictions. The default path does not import PyTorch.

The runtime adapter reads only precomputed features named by the controller-visible
observation identifier. Simulator image capture and heavyweight V-JEPA encoding are
separated from online prediction, allowing every feature lookup to be reproduced
from its observation and checkpoint hashes.

## Predictor-version revalidation guard

`ModelRegistry` records installation, replacement, and revalidation in an
append-only hash chain. `GuardedPolicyEngine` first applies the existing policy,
then makes a high-consequence result more restrictive when its predictor is
unregistered, superseded, unqualified, calibrated under a different version, or
unqualified for the requested action class. It cannot turn a base `HOLD`, `BLOCK`,
or `ESCALATE` result into a more permissive decision.

The controlled RQ5 diagnostic holds prediction values fixed while varying only
model qualification state. This isolates the guard behavior from model quality.

## Development evaluation

The registered synchronized study contains 400 independent simulator episodes.
Complete episodes are deterministically assigned to train, tuning, calibration,
and validation partitions with seeds `20260722` and `20260723`. No test episode is
generated by this campaign. Each episode contributes two counterfactual action
rows that remain in the same partition.

The camera observes depth, debris, turbulence, rain, and visibility cues. Latent
water depth and debris state are excluded from the structured input and retained
only for rendering and adjudication. Targets use the workbench zero-process-noise
water update at each action's arrival horizon. The study is conditional on delivered
drone evidence.

The official encoder input contains 16 frames sampled every four source frames,
spanning 61 source-frame intervals. This sampling matches the pinned upstream
ViT-B Kinetics-400 and COIN evaluation configurations. The registered amendment
replaced a 64-frame CPU encoding path before an official model comparison was
trained or inspected.

Reported metrics are Brier score, negative log likelihood, 10-bin expected
calibration error, AUROC, average precision, all-target MSE, per-target MAE/RMSE,
and paired 95% episode-cluster bootstrap intervals. The episode-shuffled control
permutes complete visual observations while retaining both action rows from each
episode.

## Test-data boundary

Test capture and test encoding are disabled by default. Both require a complete
freeze manifest containing protocol, code, dataset, predictor, and calibration
identifiers with `test_authorized` set to `true`. Placeholder or incomplete
manifests are rejected. No held-out test episode was generated or accessed for the
development results in this repository.

## Reproducibility, security, and limitations

Generated observations, feature arrays, checkpoints, and detailed run reports are
excluded from Git and identified by SHA-256 digests. The integration contains no
credentials, identifiable victim imagery, or operational emergency data.

The synchronized study evaluates integration, provenance, leakage resistance,
calibration, guard behavior, and simulator-channel sensitivity. It does not
establish field-video generalization, cross-domain superiority, certified safety,
or operational effectiveness in emergency response.
